حل وضع الصيانة - Core Media
========================
السبب: Vercel يخدم index.html الموجود فعليًا قبل تطبيق rewrite المعرّف في vercel.json.

التفعيل (خطوة واحدة أساسية):
1) افتح مستودع GitHub المرتبط بموقع Vercel، وعلى الفرع المستخدم للنشر (غالبًا main).
2) مهم: احفظ نسخة من index.html الحالي، أو تأكد أنه موجود في تاريخ GitHub لاستعادته لاحقًا.
3) افتح الأرشيف الحالي؛ ستجد index.html جديدًا هو صفحة الصيانة. ارفع index.html هذا إلى جذر المستودع واستبدل الملف الحالي بنفس الاسم، ولا ترفعه داخل مجلد جديد.
4) Commit changes. راقب Deployments في Vercel حتى تصبح آخر عملية نشر Ready على نطاق Production.
5) افتح رابط الموقع في نافذة Incognito، مع تحديث كامل Ctrl+Shift+R.

لا تحتاج رفع maintenance.html أو vercel.json من جديد، ولا تحتاج تشغيل Supabase.
لا تغير بقية ملفات مشروع Core Media؛ بقاء الملفات مهم لاسترجاع الموقع.

عند انتهاء التعديلات:
- من GitHub History استرجع index.html الأصلي من الـcommit السابق لوضع الصيانة، أو ارفع نسخة index.html التي احتفظت بها.
- اعمل Commit وراقب نشر Vercel.
- احذف ملف vercel.json الذي جاء من محاولة الصيانة القديمة فقط إذا لم يكن يحتوي على إعدادات مهمة أخرى؛ ليس ضروريًا لرجوع الصفحة الأصلية لأن index.html له الأولوية.

إذا ظل الموقع القديم ظاهرًا بعد ذلك:
- تأكد من أنك تعدّل المستودع والفرع اللذين يستخدمهما Vercel في Project Settings > Git.
- افتح Settings > Build and Deployment وتحقق من Root Directory وOutput Directory؛ يجب أن يكون index.html الجديد داخل المجلد المنشور.
- تحقّق من حالة Production deployment بأنها Ready، وأن عنوان النطاق متصل بآخر نشر.
- جرّب فتح الصفحة في نافذة خاصة لمسح أثر الكاش.

ملاحظة: هذه الحزمة تغيّر واجهة الموقع فقط. لا تحذف بيانات ولا تصلح مشكلة Supabase أو لوحة التحكم.
